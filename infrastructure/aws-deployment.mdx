## Current Decision

Native ONNX inference on AWS Lambda is the active deployment. The original
general-purpose Roboflow container was too large and slow for Lambda, but a
narrow multi-stage runtime solved both constraints:

| Metric | General vendor path | Native production path |
| --- | --- | --- |
| Image size | About 9.9 GB after stripping | About 585 MB |
| Public cold request | About 25-110 seconds during experiments | About 4-5 seconds |
| Public warm request | Under one second | About 0.6-0.8 seconds |
| Runtime Roboflow dependency | Metadata/package discovery remained | None |
| Primary inference dependency | Broad server + PyTorch | ONNX Runtime + OpenCV/NumPy |

The old conclusion that Lambda was abandoned is no longer correct. See
[Native Lambda Runtime Retrospective](/infrastructure/native-runtime-retrospective)
for the experiments, dead ends, exact parity gate, and final rewrite.

## AWS Topology

```text
Linode DNS
    scan.chalkysticks.com CNAME
        -> CloudFront (global)
        -> Lambda Function URL (us-east-2)
        -> Lambda container image from ECR (us-east-2)
        -> CloudWatch Logs

ACM certificate (us-east-1)
    -> attached to CloudFront

CloudFormation/SAM stack (us-east-2)
    -> Lambda
    -> Function URL
    -> IAM execution role
    -> CloudFront distribution
```

## Ownership

| Resource | Owner | Lifecycle |
| --- | --- | --- |
| Lambda function | `chalkysticks-inference` stack | `sam deploy` / `sam delete` |
| Function URL | `chalkysticks-inference` stack | `sam deploy` / `sam delete` |
| CloudFront distribution | `chalkysticks-inference` stack | `sam deploy` / `sam delete` |
| Lambda IAM role | `chalkysticks-inference` stack | `sam deploy` / `sam delete` |
| ECR repository | Created separately | Preserve across stack deletion for rollback |
| ACM certificate | Requested separately in `us-east-1` | Preserve while custom hostname is used |
| Linode DNS records | Linode | Manual |

Avoid direct changes to stack-owned resources. Manual Lambda or CloudFront
updates create CloudFormation drift.

## ECR Repository

```text
172720370877.dkr.ecr.us-east-2.amazonaws.com/chalkysticks/roboflow-table-detection
```

Authenticate:

```bash
aws ecr get-login-password --region us-east-2 \
  | docker login --username AWS --password-stdin \
    '172720370877.dkr.ecr.us-east-2.amazonaws.com'
```

The deployment tool pushes both `latest` and an immutable timestamp. It then
resolves `latest` to `repository@sha256:...` before SAM deployment so
CloudFormation sees an actual image change.

## SAM Deployment

The stack source is `bin/api-v2/docker/aws/template.yml`. The supported path is:

```bash
cd bin/api-v2
./docker/tool/run
# -> Deploy to AWS Lambda
```

The tool supplies all parameters non-interactively, including:

- immutable image digest
- `MemorySize=10240`
- custom hostname when its certificate is issued
- ACM certificate ARN
- ECR image repository mapping

Do not mix this with `aws lambda update-function-code`. We tested that path;
out-of-band image changes made the stack's recorded state diverge and led to
update/rollback failures.

## Why Not the Other Options?

| Option | Status | Reason |
| --- | --- | --- |
| Roboflow hosted inference | Available fallback | Preserves external cost and runtime dependency |
| Browser private-model inference | Not used | Ships private weights to clients |
| Main API server | Not used | Couples API and inference resource scaling |
| EC2 inference host | Viable fallback | Always-on operational cost and host management |
| ECS/Fargate | Viable at higher steady traffic | More baseline cost than scale-to-zero Lambda |
| General vendor image on Lambda | Rejected | Multi-gigabyte image and unpredictable cold initialization |
| Native ONNX Lambda | Active | Small, private, independently scalable, deterministic runtime |

## Full Retirement

Deleting the stack removes stack-owned compute and edge resources:

```bash
cd bin/api-v2/docker/aws
sam delete \
  --stack-name chalkysticks-inference \
  --region us-east-2
```

Afterward:

1. Remove `scan.chalkysticks.com` from Linode DNS.
2. Preserve ECR until the rollback retention window closes.
3. Delete the ACM certificate only after CloudFront no longer references it.
4. Delete ECR only when all rollback images are intentionally retired.

Destructive resource commands are documented on the component pages so they
remain adjacent to their warnings and recovery implications.
