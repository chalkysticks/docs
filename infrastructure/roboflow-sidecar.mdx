## Current Role

The Roboflow sidecar is a trusted local **model acquisition and comparison
environment**. It is not the production request runtime.

It runs Roboflow's official inference server on localhost, downloads a selected
model package, and preserves the vendor HTTP behavior used for parity testing.
The production Lambda later receives only the selected ONNX weights,
configuration, and class names.

```text
Roboflow (update time only)
    -> local official sidecar
    -> persistent model cache
    -> captured offline package manifest
    -> vendor-compatible standalone image
    -> native Lambda artifact extraction
```

The sidecar speaks the familiar contract:

```text
POST /{slug}/{version}?confidence=...&overlap=...&api_key=...
Body: base64 image
```

## Start

From `bin/api-v2`:

```bash
docker compose -f docker/inference/compose.cpu.yml up -d
```

This creates:

1. `chalkysticks-inference` — official acquisition server on
   `127.0.0.1:9001`
2. `chalkysticks-inference-warmup` — one-shot model acquisition and manifest
   capture

The recommended entry point is the menu tool:

```bash
./docker/tool/run
# -> Start (CPU)
```

## Configure the Active Model

The current combined model is:

```dotenv
ROBOFLOW_DETECTION_MODEL_URL=http://127.0.0.1:9001/balls-and-pockets-qi5jc/4
ROBOFLOW_WARMUP_MODELS=balls-and-pockets-qi5jc/4
```

The warmup script prefers `ROBOFLOW_DETECTION_MODEL_URL`. It retains support
for the legacy `ROBOFLOW_MODEL_URL` plus
`ROBOFLOW_BALLDETECTION_MODEL_URL` pair, but the native Lambda builder requires
exactly one active combined model.

`ROBOFLOW_API_KEY` is required while downloading a new model package. It is not
used by deployed native Lambda requests.

## Warmup and Offline Manifest

Watch acquisition:

```bash
docker compose -f docker/inference/compose.cpu.yml logs -f warmup
```

Expected output includes:

```text
[warmup] -> balls-and-pockets-qi5jc/4
[warmup]    cached (200)
[warmup]    offline manifest saved
[warmup] All models warmed successfully. Cache is ready to build an offline image.
```

The weights live in the named Docker volume `chalkysticks-model-cache`, mounted
at `/tmp/cache` in the official container.

```bash
docker exec chalkysticks-inference du -sh /tmp/cache
docker exec chalkysticks-inference find /tmp/cache -name model-metadata.json -print
```

## Important Correction: Weights Alone Are Not Offline

An early assumption was that a warm weight cache removed Roboflow from the
runtime path. Testing a fresh process showed that the official server still
requested model-package metadata before associating cached blobs with a model.

`warmup.sh` now captures `model-metadata.json` during the authorized update
phase. `offline_app.py` installs a local metadata provider and redirects any
missing-artifact fallback to a loopback-only failure. The standalone image
therefore either runs fully offline or fails locally; it does not silently call
Roboflow.

## Test the Vendor Runtime

Menu shortcuts:

```bash
./docker/tool/run
# -> Test inference (smoke)
# -> Test inference (real image)
```

Direct request:

```bash
base64 -i /path/to/table.jpg | curl -sS -X POST \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-binary @- \
  'http://127.0.0.1:9001/balls-and-pockets-qi5jc/4?confidence=0.4&overlap=0.3' | jq
```

Use this output as the vendor side of native parity testing.

## Build the Standalone Vendor Artifact

```bash
./docker/tool/run
# -> Build standalone image
```

The command refuses to build unless the active model has both cached package
files and its captured manifest. It produces:

```text
chalkysticks/inference:latest
```

This image has two roles:

- strict offline vendor-compatible debugging
- immutable artifact source for `Dockerfile.lambda-native`

It is intentionally not the small production image. The native multi-stage
build copies only `weights.onnx`, `inference_config.json`, and
`class_names.txt` into the final Lambda runtime.

## Updating Models

Do not rely on the first production request to download a model. Use the
controlled release flow:

1. Point `ROBOFLOW_DETECTION_MODEL_URL` at the new local slug/version.
2. Optionally export the old cache.
3. Stop and clean the local cache for an independently complete release.
4. Start CPU acquisition and wait for manifest capture.
5. Test official output on representative images.
6. Build the standalone artifact.
7. Build the native Lambda candidate.
8. Require vendor/native parity.
9. Push and deploy through CloudFormation.

See [Roboflow Model Sync and Release](/infrastructure/model-release) for the
complete operational sequence.

## GPU Variant

For a compatible NVIDIA host:

```bash
docker compose -f docker/inference/compose.cpu.yml down
docker compose -f docker/inference/compose.gpu.yml up -d
```

CPU and GPU compose files share `chalkysticks-model-cache`. GPU acquisition can
help local experimentation, but the production Lambda runtime uses ONNX Runtime
on arm64 CPU.

## Stop and Clean Up

Stop containers without removing the persistent cache:

```bash
docker compose -f docker/inference/compose.cpu.yml down
docker compose -f docker/inference/compose.gpu.yml down
```

Use **Cleanup** in `./docker/tool/run` to remove the cache volume. Cleanup is
destructive to local cached packages, so export first when a backup matters.

## Environment Reference

| Variable | Role |
| --- | --- |
| `ROBOFLOW_API_KEY` | Authorized model acquisition only |
| `ROBOFLOW_DETECTION_MODEL_URL` | Active combined local model URL |
| `ROBOFLOW_WARMUP_MODELS` | Optional explicit warmup slug/version |
| `MODEL_CACHE_DIR` | Official server cache location; `/tmp/cache` in compose |
| `METRICS_ENABLED` | Set to `False` |
| `NUM_WORKERS` | Official server worker count |
| `HOST` / `PORT` | Local service bind; port 9001 outside Lambda |

## Boundaries

- Port 9001 is bound to localhost so the acquisition server is not public.
- The broad official image may remain multi-gigabyte; production does not ship it.
- Cached weights without `model-metadata.json` are not offline-complete.
- A new ONNX package is not automatically compatible with the native adapter.
- The private production model is never intentionally distributed to browsers.
