## Current Architecture

ChalkySticks table scanning uses a private RF-DETR ONNX model in an on-demand
AWS Lambda. CloudFront provides the stable `scan.chalkysticks.com` hostname.
The production request path has no runtime dependency on Roboflow:

```text
Client or Laravel API
    -> CloudFront / scan.chalkysticks.com
    -> Lambda Function URL
    -> native FastAPI + ONNX Runtime
    -> weights baked into the private ECR image
```

Roboflow remains part of the explicit update process on a trusted developer
machine:

```text
Roboflow model version
    -> local acquisition sidecar
    -> persistent cache + offline package manifest
    -> vendor-compatible standalone artifact
    -> three selected native model files
    -> small Lambda image
    -> ECR + CloudFormation deployment
```

This separation provides:

- independent, scale-to-zero inference compute
- no Roboflow request charges or availability dependency at runtime
- no model weights shipped to browsers
- a stable custom HTTPS endpoint without EC2 or nginx
- deterministic model/version rollbacks through immutable ECR tags

## What Runs Where

| Component | Role | Roboflow access |
| --- | --- | --- |
| Local official sidecar | Acquire and compare model packages | Only when warming a new version |
| Standalone image | Offline vendor-compatible debugging and artifact source | None |
| Native Lambda image | Production inference | None |
| Laravel API post-evaluation | Ball appearance, identity assignment, homography, controller response | None |
| Browser SDK | Chroma analysis and optional local development models | Production private weights are not shipped |

## Quick Health Check

```bash
curl -fsS https://scan.chalkysticks.com/ | jq
```

Expected:

```json
{
  "status": "ok",
  "runtime": "native-offline-rfdetr-onnx"
}
```

If the custom domain is not active, use
`https://di7v13w34zitn.cloudfront.net/` to isolate DNS/certificate setup from
Lambda health.

## Deployment Entry Point

```bash
cd bin/api-v2
./docker/tool/run
```

The current tool owns local acquisition, cache backup, offline builds, native
Lambda builds, ECR pushes, SAM deployment, and basic inference tests. The
longer-term home for cross-project operations is the global `chalky` CLI; see
[Inference Tool](/infrastructure/inference-tool) for the current boundary and
migration candidates.
