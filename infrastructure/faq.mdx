### How do I check it?

```bash
curl -fsS https://scan.chalkysticks.com/ | jq
```

```bash
base64 -i /path/to/table.jpg | curl -sS -X POST \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-binary @- \
  'https://scan.chalkysticks.com/balls-and-pockets-qi5jc/4?confidence=0.4&overlap=0.3' | jq
```

If the custom hostname fails, test the CloudFront fallback, then the direct
origin. That isolates DNS/certificate, edge, and Lambda failures in order.

### How does the API call it?

`app/Services/Roboflow.php` sends a base64 image to the configured model URL.
The combined model is configured through:

```dotenv
ROBOFLOW_DETECTION_MODEL_URL=https://scan.chalkysticks.com/balls-and-pockets-qi5jc/4
```

The native runtime preserves the response contract, so the PHP client does not
need a provider-specific branch. Restart PHP-FPM and queue workers after
changing environment configuration.

### I changed ball-evaluation formulas. Do I rebuild Lambda?

No. Appearance analysis, duplicate/missing identity resolution, homography, and
controller formulas run in the Laravel API after raw model inference. Test and
deploy the API only.

Rebuild Lambda when native image preprocessing/postprocessing changes or when
the baked model package changes.

### I created a new Roboflow model version. What now?

Do not point production at Roboflow or let a production request download it.
Follow [Roboflow Model Sync and Release](/infrastructure/model-release):

1. Acquire the package locally.
2. Capture its offline manifest.
3. Test official output.
4. Build the standalone artifact.
5. Build the native image.
6. Require vendor/native parity.
7. Push immutable ECR tags.
8. Deploy through CloudFormation.
9. Switch the API model path.

## Sidecar and Model Acquisition

### Warmup cached weights but the standalone image still calls Roboflow

Weights alone are insufficient. A fresh official process may still request
package metadata. Successful warmup must include:

```text
[warmup]    offline manifest saved
```

Verify `model-metadata.json` exists for the active slug/version before building
the standalone image.

### Warmup says the API key is empty

`bin/api-v2/.env` must define `ROBOFLOW_API_KEY` during acquisition. The key is
not needed by the deployed native runtime.

### Model package has ONNX weights but the native build rejects it

An `.onnx` extension does not prove compatibility. The current adapter expects
the RF-DETR tensor, resize, RGB, normalization, and class-operation contract
used by `balls-and-pockets-qi5jc/4`.

Inspect input/output names and shapes plus `inference_config.json`, implement a
new adapter when needed, and require vendor/native parity before deployment.

### How do I inspect local cache and images?

```bash
docker exec chalkysticks-inference du -sh /tmp/cache
docker exec chalkysticks-inference find /tmp/cache -name model-metadata.json -print
docker image inspect chalkysticks/inference:latest --format '{{.Size}}'
docker image inspect chalkysticks/inference:lambda --format '{{.Size}} {{.Architecture}}'
```

## CloudFront and Certificate

### ACM stays `PENDING_VALIDATION`

Confirm every authoritative nameserver returns the validation CNAME and that
Linode did not append the zone twice:

```bash
dig +short NS chalkysticks.com
dig +short CNAME _ac7bd1cffd9d6ba6ec5709ccb7c5a922.scan.chalkysticks.com @ns1.linode.com
```

The expected target is:

```text
_4bdded0e21bfdd57ad357b8c45fb451c.jkddzztszm.acm-validations.aws.
```

ACM can remain pending for several minutes after public DNS is correct. Keep
the validation CNAME after issuance for renewal.

### CloudFront says it cannot find a certificate

CloudFront only lists issued ACM certificates from `us-east-1`. Do not create a
duplicate certificate while the intended one is pending. Wait for `ISSUED`,
then rerun **Deploy to AWS Lambda** so CloudFormation attaches the alias.

### CloudFront hostname works but `scan.chalkysticks.com` fails

Check:

1. `scan` resolves to `di7v13w34zitn.cloudfront.net`.
2. ACM is `ISSUED` in `us-east-1`.
3. Stack outputs include `CustomDomainUrl`.
4. The distribution alias includes `scan.chalkysticks.com`.
5. The certificate covers the exact hostname or a valid one-level wildcard.

### Why not CNAME directly to the Function URL?

DNS does not rewrite TLS certificates or HTTP `Host`. The Function URL's
certificate covers its AWS hostname, not `scan.chalkysticks.com`. CloudFront
terminates TLS for the custom domain and sends the expected origin host.

### CloudFront returns 403

Verify the distribution uses `AllViewerExceptHostHeader`. Forwarding the
viewer `Host` to the Function URL can prevent Lambda from accepting the origin
request.

### Could inference responses be cached?

No. The behavior must use AWS managed `CachingDisabled`. Cached health or model
responses can hide deployments and return another request's inference result.

## Lambda

### ONNX Runtime aborts while reading `/sys/devices/system/cpu/*`

The final image must preload `/opt/cpuinfo-shim.so`. The shim supplies CPU range
`0-5`, matching the approximately six vCPUs at 10240 MB. Rebuild with
`Dockerfile.lambda-native` and confirm `LD_PRELOAD` is present.

### Lambda returns a strange response from port 9001

Lambda reserves port 9001 for its Runtime API. The native FastAPI application
must listen on 8080, with Lambda Web Adapter forwarding invocations there.

### Cold requests exceed ten seconds

Check:

1. The deployed image is the approximately 585 MB native image, not the vendor artifact.
2. Lambda memory is `10240 MB`.
3. The CPU shim reports `0-5`.
4. ONNX intra-op threads are six.
5. The model package has not changed to a materially larger graph.
6. CloudWatch `REPORT` lines for `Init Duration` and execution duration.

Expected initial native measurements were 4-5 seconds cold and 0.6-0.8 seconds
warm.

### The root filesystem is read-only

That is normal for Lambda. Model artifacts stay immutable in the image; only
`/tmp` is writable. Test candidates with `--read-only` and a `/tmp` tmpfs before
deployment.

## CloudFormation and Rollback

### A pushed `latest` image did not update Lambda

CloudFormation compares the `ImageUri` string, so `:latest` to `:latest` can be
a no-op. The deployment tool resolves `latest` to its `sha256` digest and passes
`repository@sha256:...` into SAM.

### Stack is `UPDATE_ROLLBACK_FAILED`

This often follows an out-of-band `aws lambda update-function-code`. Stop
direct function updates and return ownership to CloudFormation:

```bash
aws cloudformation continue-update-rollback \
  --stack-name chalkysticks-inference \
  --region us-east-2
```

If a resource must be skipped, investigate the exact stack event before using
`--resources-to-skip`; skipping can leave drift that needs reconciliation.

### How do I roll back a model?

Move ECR `latest` to the known-good immutable timestamp tag and run **Deploy to
AWS Lambda** again. Restore the API URL's model path if the release changed
slug/version. Exact commands are in
[Lambda Inference Service](/infrastructure/lambda-inference).

### How do I stop or delete everything?

Use the lifecycle sections in:

- [Lambda Inference Service](/infrastructure/lambda-inference)
- [CloudFront Inference Edge](/infrastructure/cloudfront-inference)

For an emergency stop, set Lambda reserved concurrency to zero. For full
retirement, use `sam delete`; preserve ECR and ACM until their rollback and
certificate responsibilities are intentionally ended.

## Privacy Boundary

### Can we ship this model in the browser SDK?

Technically yes, but that exposes the weights to every client. The current
private production model stays in ECR/Lambda. Browser inference and browser
model caching are appropriate only for intentionally distributable models or
development experiments.
