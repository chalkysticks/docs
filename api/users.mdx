## List Users

```bash
GET /v3/users
GET /v3/users?q=matt
GET /v3/users?limit=25
```

## Get User

```bash
GET /v3/users/{user}
```

**Response:**
```json
{
  "data": {
    "id": 1,
    "name": "Matt Kenefick",
    "avatar": "https://...",
    "created_at": "2025-01-01T00:00:00Z"
  }
}
```

## Privacy Boundary

Public profiles use `/v3/users/{user}`. Private account state is exposed through authenticated `/v3/users/{user}/...` resources and is limited to the owner or an administrator. Putting another user's id in the URL does not grant access.

Private successful responses, authorization failures, and writes never enter shared cache.

## Owned Products

The global `/v3/products` collection is the public product catalog. Products owned by a specific account are separate private resources:

```bash
GET /v3/users/{user}/products
Authorization: Bearer YOUR_TOKEN
```

Optional filter: `type=digital` or `type=physical`.

## Entitlements

Durable cosmetic inventory is private to the owner or an administrator:

```bash
GET /v3/users/{user}/entitlements
GET /v3/users/{user}/entitlements?active=1&category=cue
Authorization: Bearer YOUR_TOKEN
```

## Loadouts

Equipped cosmetics are public profile presentation data:

```bash
GET /v3/users/{user}/loadouts
GET /v3/users/{user}/loadouts/{category}
```

Writes are owner-or-administrator only:

```bash
POST /v3/users/{user}/loadouts
PUT /v3/users/{user}/loadouts/{category}
DELETE /v3/users/{user}/loadouts/{category}
Authorization: Bearer YOUR_TOKEN
```

Collection-level upsert accepts `category` and `item_key`. Category-level update accepts `item_key`.

## Private Match History

```bash
GET /v3/users/{user}/matches
Authorization: Bearer YOUR_TOKEN
```

Use this endpoint for a match inbox or complete history. `/v3/matches?user_id={user}` is the public, identity-independent match listing.
