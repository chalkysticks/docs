---
title: 'Process a Video Stream'
description: 'Continuously scan a camera or video source for current ball positions'
---

Use `Scan.live()` as the stable product-level entry point for a camera or
playing video. It returns a `Scan.LiveScanner` immediately, starts processing,
and emits canonical `Inference.IProcessedFrame` results through its `frame`
event.

## Continuous Live Scanning

```typescript
import * as ChalkySticks from '@chalkysticks/sdk-inference';

const video = document.querySelector<HTMLVideoElement>('video');

if (!video) {
	throw new Error('A video element is required');
}

const scanner = ChalkySticks.Scan.live(video, {
	framesPerSecond: 'maximum',
});

scanner.on('frame', (event) => {
	const frame: Inference.IProcessedFrame = event.data;
	const balls = frame.transformedData?.balls ?? [];

	renderProjection(balls);
});

scanner.on('error', (event) => {
	console.error('Live scan failed', event.data);
});

// Later, when the projection mode closes:
await scanner.dispose();
```

`Scan.live()` always enables canonical table-space transformation. Read
`frame.transformedData.balls` when projection coordinates are required, and
read `frame.balls` when source-image coordinates are more useful.

## Camera Input

The scanner consumes an existing `HTMLVideoElement`, so camera acquisition and
permission remain with the application:

```typescript
const stream = await navigator.mediaDevices.getUserMedia({
	audio: false,
	video: {
		facingMode: 'environment',
	},
});

video.srcObject = stream;
await video.play();

const scanner = ChalkySticks.Scan.live(video);
```

Stop the stream tracks separately after disposing the scanner because the
application, not the SDK, owns the camera stream.

## Cadence

Live scanning defaults to one processed frame per second. This keeps hosted
inference predictable when a caller does not select a throughput policy.

```typescript
const scanner = ChalkySticks.Scan.live(video); // 1 FPS

scanner.setFramesPerSecond(5); // cap accepted source frames at 5 FPS
scanner.setFramesPerSecond('maximum'); // process newest frames as fast as inference completes

console.log(scanner.getFramesPerSecond());
```

Slow inference never creates a frame backlog. While one frame is in flight,
newer source frames are skipped. The next eligible source frame is processed
when the engine becomes available.

## Engine Selection

Without an explicit engine, the scanner uses the SDK's stable hosted scan
engine. An advanced integration can inject any `Inference.IInferenceEngine`:

```typescript
const engine = ChalkySticks.Scan.createHostedEngine({
	maximumConcurrentRequests: 1,
});
const scanner = ChalkySticks.Scan.live(video, {
	engine,
	framesPerSecond: 'maximum',
});
```

An injected engine remains owned by the caller and is not disposed with the
scanner. This makes it possible to keep a model warm across scanner instances.

## Lower-Level Processing

Use `Core.ImageAnalyzer` directly only when an integration needs control over
the internal processing pipeline. `Scan.LiveScanner` is the compatibility
boundary intended for application code while detection techniques evolve.

`Scan.sweep()` is a different workflow: it captures interval-spaced views of a
mostly static table and fuses them into one multi-view result. It is not the
continuous projection scanner.
