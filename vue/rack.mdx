`ChalkyRackDiagram` draws a rack of balls as resolution-independent SVG. The
arrangement comes from [`ChalkySticks.Game.Rack`](/sdk/game/racking), which owns
the lattice and the racking rules for every game, so an eight ball drawn here
sits where an eight ball sits in the trainer. The component owns only the
drawing.

```html
<ChalkyRackDiagram strategy="EightBall" />
```

## RackDiagram

### No intrinsic size

The `<svg>` carries **no `width` or `height`** — only a `viewBox` measured from
the artwork. The host decides how large it renders by sizing the element, and
the aspect ratio follows the rack:

```html
<div style="width: 320px">
    <ChalkyRackDiagram strategy="EightBall" />
</div>
```

The box is measured from the balls' edges *and* the frame's mitred corners, not
from ball centres. A sharp corner pushed outward by one clearance reaches out
roughly twice that far, so a box measured from the balls alone would crop the
corners. Measuring properly means the diagram survives export, rasterization,
and hosts that clip overflow.

### Props

| Prop | Type | Notes |
|------|------|-------|
| `strategy` | string | `EightBall` (default), `NineBall`, `TenBall`, `ThreeBall`, `OneBall`, `Rotation`, `StraightPool`, `DrillLine` |
| `seed` | string | Makes the arrangement repeatable. Empty picks one once, on creation |
| `balls` | array \| object | Ball number per position ordinal; gaps fall to the solver |
| `ballSet` | string | Ball set identifier. Empty uses the renderer's own default |
| `ballStyle` | string | `flat`, `shaded`, `chalky-classic`, `trainer` |
| `orientation` | number | Quarter turn in degrees: `0`, `90`, `180`, `270` |
| `mirror` | boolean | Flip across the long axis |
| `pattern` | string | Bare shape override: `triangle`, `diamond`, `line`. No racking rules applied |
| `rows` | number | Row count for `pattern` |
| `showCueBall` | boolean | Draw a cue ball in front of the apex |
| `showOutline` | boolean | Draw the rack frame (default `true`) |
| `showPositionLabels` | boolean | Number each position, for teaching |
| `background` | string | Fill painted behind the rack. Empty is transparent |
| `padding` | number | Margin around the drawn rack, in ball diameters (default `0.25`) |
| `interactive` | boolean | Make each ball focusable and emit `select` |
| `decorative` | boolean | Hide from assistive technology as pure decoration |
| `title` | string | Accessible description. Empty describes the rack itself |

Emits: `change` (the arrangement, whenever it is re-solved), `ready` (once, after
the first solve), `select` (a ball was activated — only when `interactive`).

Slots: `default` (drawn inside the SVG above the balls, scoped
`{ balls, unit, viewBox }`), `caption` (visible caption below the diagram),
`outline` (replace the frame, scoped `{ path, viewBox }`).

Public method: `shuffle(seed?)` — re-solve, optionally against a seed you choose.

### Repeatability

An unseeded diagram picks a seed once when it is created and holds it, so it
does not re-rack on every render. Pass `seed` when the arrangement has to be
the same every load — a screenshot, a shared link, a documentation figure:

```html
<!-- A legal eight-ball rack, different every load -->
<ChalkyRackDiagram strategy="EightBall" />

<!-- The same rack every load -->
<ChalkyRackDiagram seed="tuesday-league" strategy="EightBall" />
```

### Placing specific balls

Positions are numbered from the apex and keep their numbers however the rack is
turned. `null` leaves a position to the solver, which fills the rest legally
around whatever you pinned.

```html
<ChalkyRackDiagram
    strategy="EightBall"
    :balls="[1, null, null, null, 8]"
    :showPositionLabels="true"
/>

<!-- Or address one position at a time -->
<ChalkyRackDiagram strategy="NineBall" :balls="{ 0: 9, 4: 1 }" />
```

<Note>
	A hand-placed ball outranks the requirement for that slot. Pin the 8 at the
	apex of an eight-ball rack and the centre spot takes a leftover ball rather
	than holding a duplicate.
</Note>

### Ball sets

Artwork is generated by [`sdk-renderer-2d`](/sdk/renderer-2d) — the same source
the Pad draws from. `chalkysticks-pool` is the default.

```html
<ChalkyRackDiagram ballSet="chalkysticks-classic" strategy="EightBall" />
<ChalkyRackDiagram ballSet="snooker-flat" strategy="TenBall" />
```

Racking is a pool idea, so a rack always names its balls by number — but a
snooker or carom set names its balls by colour and has no ball called "9".
Asking such a set for one yields the renderer's neutral fallback, which draws a
row of grey discs. The component instead falls back to the set's own object
balls in order, so a snooker set looks like snooker.

### Accessibility

The root is a `<figure>`; the `<svg>` is `role="img"` with an
`aria-labelledby` pointing at an in-SVG `<title>` that describes the rack from
its own solution. Set `title` to override it, or `decorative` to hide the
diagram from assistive technology entirely. The `caption` slot renders a visible
`<figcaption>`, which beats a title for teaching.

### Several on one page

Every fragment identifier is namespaced per component instance. Two diagrams
with different ball sets on the same page cannot resolve each other's artwork,
which is otherwise easy to hit: `<use xlink:href="#ball-1">` resolves against
the first matching id in the whole document.
